# Author Reports

Author-engageable summaries built from the campaign work in this repository. Each report consolidates relevant material across the per-PR campaign documents and the verification findings, in a form a known collaborator can read in one sitting and respond to.

This folder is scoped to *this kind of artifact* (focused interim summaries written for a single collaborator). It is **not** a journal-manuscript folder; the verification + campaign documents under `Roadmapping/Equation_Verification/`, `Roadmapping/Electromagnetism/`, `Roadmapping/Quantum_Mechanics/`, etc. remain the source-of-truth.

## Naming convention

`{YYYY}-{MM}_{report_type}_for_{recipient}.{ext}` (lowercase).

Examples:
- `2026-05_interim_for_gill.md`
- `2026-05_interim_for_gill.tex` (generated by build)
- `2026-05_interim_for_gill.pdf` (generated by build)

The folder may host multiple reports over time. The naming convention keeps it navigable.

## Deliverable types per report

Three artifacts per report, all committed:

- **`.md`** — markdown source-of-truth. Per-paragraph `<!-- TODO: human reviews and fills in -->` blocks are retained here for the human-acceptance pass before the PDF is built. GitHub renders the markdown with relative cross-references intact.
- **`.tex`** — LaTeX source produced by `build_report.sh` from the markdown. Derived artifact; do not hand-edit (re-run the build instead).
- **`.pdf`** — built PDF, the artifact a recipient actually receives. Committed only after the human-acceptance pass on the `.md` completes (see "Phase ordering" below).

## Build pipeline (`build_report.sh`)

Single-command build:

```bash
./build_report.sh <report_basename>
# e.g.:
./build_report.sh 2026-05_interim_for_gill
```

The script:

1. Strips `<!-- ... -->` HTML comments (the per-paragraph TODO markers) from a working copy of the `.md`.
2. Runs `pandoc` to convert the stripped markdown → LaTeX.
3. Runs `pdflatex` twice (for cross-references) to produce the PDF.
4. Defensive check 1: fails the build if any `<!-- TODO` substring is still present in the LaTeX after stripping (catches stripper bugs).
5. Defensive check 2: fails the build if the PDF page count is outside `[3, 7]` (per the length-budget discipline in the report's plan).

Use `--dry-run` to exercise the pipeline without committing the PDF:

```bash
./build_report.sh 2026-05_interim_for_gill --dry-run
```

The dry-run mode builds everything in a temporary directory and reports success/failure without writing the `.tex` / `.pdf` to the repository. This is the mode Phase 3 of the plan exercises before the human-acceptance pass.

### System dependencies

- `pandoc` (≥ 3.x recommended; tested against 3.1.3)
- `texlive-latex-base`, `texlive-latex-extra`, `texlive-pictures` (already required for the Manim sub-project per [`CLAUDE.md`](../../CLAUDE.md))
- `poppler-utils` (for `pdfinfo`)

Install on Debian/Ubuntu:

```bash
sudo apt-get install pandoc texlive-latex-base texlive-latex-extra texlive-pictures poppler-utils
```

### Reproducibility scope

The build is *rebuildable* from the same `.md` on a clean checkout without manual intervention. It is **not** byte-identical-deterministic across machines — pandoc + pdflatex output varies with toolchain versions, font availability, and `/tmp` paths embedded by some LaTeX packages. The build script pins the PDF metadata date via `--metadata date=<YYYY-MM-DD>` so timestamp drift does not leak into the output, but full byte-identical determinism would require a pinned container that is out of scope.

## Phase ordering for a new report

The phases below are the discipline that the plan for `2026-05_interim_for_gill` (issue [#58](https://github.com/temoTxt/PyPhysics/issues/58)) established. Future reports should follow the same pattern.

| Phase | Scope | PDF committed? |
|---|---|---|
| 1 | Scaffold the folder + build script | no |
| 2 | Draft the `.md` source with per-paragraph TODO blocks | no |
| 3 | Dry-run the build pipeline (verify mechanics on the actual draft) | **no** |
| 3.5 | Devil's-advocate self-review + steel-man patches to the `.md` | no |
| 4 | Human-acceptance pass on the `.md` + build the final PDF | **yes** (end of phase) |
| 5 | PR opened that closes the report's tracking issue | yes |

**The PDF must not be committed before Phase 4.** Shipping an AI-drafted PDF before a human reviews it would materially violate Crocco §5 substantive-AI compliance (per [`CROCCO_COMPLIANCE.md`](../Tooling/CROCCO_COMPLIANCE.md)) — the human-acceptance pass is where the per-paragraph TODO blocks get resolved, and stripping them before review hides the markers from the reviewer.

## Writing standard (per [#115](https://github.com/temoTxt/PyPhysics/issues/115))

Every report committed to this folder must conform to the writing standard codified in [`Roadmapping/Tooling/VOICE_MATCH_GILL.md`](../Tooling/VOICE_MATCH_GILL.md), specifically §3.bis (equation discipline) and §3.ter (sentence-length discipline).

The two hard requirements:

1. **Numbered display equations only.** Every result-bearing or label-carrying equation is set as a display equation with a number. Inline math is permitted only for single-symbol references to an already-established quantity. See VOICE_MATCH_GILL.md §3.bis.
2. **Short complete sentences.** One claim per sentence. No 50-word multi-clause sentences. See VOICE_MATCH_GILL.md §3.ter.

Reports written before 2026-06-01 carry a status banner at the top of the `.md` flagging their pre-standard status. They are rewritten in follow-up PRs, not left as-is for new recipients.

The Phase 3.5 devil's-advocate self-review (see Phase ordering above) must include an explicit pass-or-fail check against §3.bis and §3.ter. A report that fails the standard does not advance to Phase 4 until rewritten.

## Crocco compliance

Author reports are **substantive AI** end-to-end (every page interprets the campaigns' results for an author audience). Three rules:

- Per-paragraph `<!-- TODO: human reviews and fills in -->` blocks in the markdown source, retained for the human reviewer.
- No AI-fabricated citations — cite only existing bib stubs under `Roadmapping/History/Bibliography/`.
- `Author = Trey Morris with Claude Opus 4.7` in PDF metadata is honest pragmatic-AI tooling attribution, *not* journal authorship; AI is never an author on a manuscript byline.

The PDF stripping the TODO markers happens at build time in Phase 4 *after* the human reviewer has resolved them, not before.
